# 控制台（AlphaMaster.exe）

一个 exe，双击打开界面，在里面启停训练和实盘。**关掉窗口，所有子进程一起退出。**

替代之前的一堆入口：

| 原来 | 现在 |
|---|---|
| `start.bat` / `start_web.bat` / `stop.bat` | 总览页的「训练台」卡片 |
| `run_btc.bat` / `run_trade.bat` | 实盘页的两个开关 |
| 看板 18780 / 18790 / am 18800 各开一个窗口 | 一个窗口四个页签 |

---

## 一、启动

双击 `AlphaMaster.exe`（项目根目录）。

首次运行会在 exe 旁边生成 `cockpit.json`，自动探测三样东西：

```json
{
  "alphamaster": "E:\\工作\\AlphaMaster",
  "factor_governor": "E:\\工作\\缠论助手\\factor-governor",
  "python": "E:\\工作\\AlphaMaster\\.venv\\Scripts\\python.exe",
  "port": 18888
}
```

路径变了就改这个文件，不用重新打包。

启动后界面是一个**无地址栏的应用窗口**（Edge/Chrome 的 `--app` 模式），
标题「AlphaMaster 控制台」。不需要浏览器里的标签页，也不会和日常浏览混在一起。

---

## 二、界面

**总览** — 三张服务卡（训练台 / XAUUSD 实盘 / BTCUSDT 实盘）+ 品种卡（权益、持仓、模型、信号）

**训练** — 选数据文件、填步数/成本、勾「从零开始」，点开始。右侧实时显示
步数、最优分、运行时长和日志尾部。

**实盘** — 每个品种一个开关，可勾 dry-run（只算不下单）。启动后每根 bar 收盘触发。

**日志** — 任何服务的输出尾部，2.5 秒刷新。

---

## 三、「关掉就全停」是怎么保证的

三层，从软到硬：

**1. 窗口消失 → 主动优雅停止**

后台线程每 1.2 秒用 `FindWindowW` 找标题为「AlphaMaster 控制台」的窗口，
连续两次找不到就判定用户关了窗口，开始收尾。收尾顺序固定：
实盘 → 训练 → 训练台 → 按端口兜底清理。

**2. Ctrl+Break 让子进程自己收尾**

实盘执行器只在 `KeyboardInterrupt` 分支里写 `stopped` 心跳、做持仓收尾。
直接 `TerminateProcess` 会跳过这些。所以用 `AttachConsole` 挂到子进程的私有
控制台，投递 `CTRL_BREAK`（定向到它的进程组）。

实测过的三种组合：

| 子进程控制台 | 信号 | 结果 |
|---|---|---|
| 独立 | `CTRL_C` 广播 | 投递成功但毫无反应 |
| 独立 + 新进程组 | `CTRL_C` 定向 | 同上（新进程组默认禁用 Ctrl+C） |
| 独立 + 新进程组 | `CTRL_BREAK` 定向 | ✅ 子进程立刻收到 |

`CTRL_BREAK` 默认是硬终止，所以 `factor_governor/executor.py` 里把 `SIGBREAK`
映射成了 `KeyboardInterrupt`，让它走同一条清理路径。

**3. Job Object 兜底**

所有子进程在启动后被 `AssignProcessToJobObject` 塞进一个作业对象，带
`JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE`。本进程一消失（正常退出、崩溃、任务管理器
结束都算），内核直接连带杀掉作业里所有进程——不依赖「我们记得去清理」。

两条链路都实测过：

```
python tools/verify_close.py   # 点关闭 → PASS 关窗后全部退出
python tools/verify_kill.py    # 强杀   → PASS 强杀也会连带清理
```

## 四、训练

走的还是原来那条命令，只是参数从表单来：

```
python <factor-governor>/tools/train_with_cost.py \
  --data-file <数据文件> --steps <步数> --cost <成本> [--from-scratch]
```

- **续训**：不勾「从零开始」就接着该品种最近的检查点跑
- **成本**：单边成本率，BTC 用 0.0005（5bp），黄金沿用默认
- **进度**：从 `training_history_<品种>.json` 读，2.5 秒刷新

⚠️ **续训会让 `strategies/best_<品种>.json` 的最优值回退。** 训练历史按当前
检查点的 best 重建，所以新进程的「最优」从较低的水平重新累计，跑满后会覆盖
公式文件。续训前先看一眼这个文件，需要时用 `git checkout -- strategies/` 恢复
（已实测踩过一次：XAUUSD 从 1.5602 掉到 1.4078）。

---

## 五、实盘

两个 loop 都通过 `factor_governor.executor loop` 启动，参数来自
`cockpit.json` 的 `live` 段，界面只能开关和选 dry-run：

```json
"live": {
  "btcusdt": {
    "symbol": "BTCUSDT", "timeframe": "M15", "broker": "binance",
    "db": "...\\runs\\live_btc.db",
    "extra": ["--max-lot", "5", "--sl-pct", "1.5", "--daily-loss", "0.05", "--max-spread-bp", "5"]
  }
}
```

要改止损、手数、点差阈值就改这里再重启控制台。

---

## 六、打包

```bash
.venv/Scripts/python.exe -m pip install pyinstaller   # 一次性
python build_exe.py --clean
```

产物 `dist/AlphaMaster.exe` 会复制到项目根目录，约 8MB。exe 内嵌的是打包时的
Python，**不含 torch** —— 真正的训练和实盘仍由 `.venv` 里的 python 执行，
exe 只做进程编排和界面，所以体积小、启动快。

## 七、排查

| 现象 | 原因 / 处理 |
|---|---|
| 双击没反应 | 看 `logs/cockpit/cockpit.log`；大概率是路径探测失败，手动改 `cockpit.json` |
| 只开了浏览器没开应用窗口 | 没装 Edge/Chrome，退化成默认浏览器，此时关标签页不会停服务 |
| 服务卡一直「启动中」 | 该服务端口被占。训练台默认 18765，先 `netstat -ano | findstr 18765` |
| 训练页显示「外部训练」 | 有别的进程在训练（不是本控制台起的），只能去原处停 |
| 已有实例在跑 | 再次双击只会打开窗口指向已有实例，不会起第二套进程树 |

日志都在 `logs/cockpit/`：`cockpit.log`（编排）、`web.log`、`xauusd.log`、
`btcusdt.log`、`train.log`。

## 八、和旧 bat 的关系

旧 bat 仍然可用，但**不要和控制台同时用**：两边都能起训练，会变成两个进程抢
同一份检查点（`tools/launch.py` 的注释里记着这个坑）。迁移完成后建议只留 exe。
