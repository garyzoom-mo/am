# 决策树因子治理：可行性评估与改造方案

> 评估对象：`E:\工作\AlphaMaster`（AlphaGPT 因子挖掘系统）
> 评估日期：2026-11-17
> 结论：**可行**，但需先纠正三个前提：系统里没有"因子权重"这个对象；决策树不能做有监督预测；候选因子的来源分两层，成本差十倍。

## 2. 可行性判断（按因子层级拆开）

"新因子"在这套系统里对应三个完全不同的层级，改造成本相差一个数量级：

| 层级 | 含义 | 新增代价 | 判断 |
|---|---|---|---|
| **L1 特征** | 65 个原始特征之一（`FEATURE_REGISTRY`） | 改 `VOCAB_VERSION` + `INPUT_DIM` → **全部 checkpoint 作废，必须从头训练** | 可行但高危，不宜频繁 |
| **L2 公式因子** | token 序列（现有挖掘产物） | 零风险，直接进候选集 | **推荐主路径** |
| **L3 组合层** | 多因子加权合成 | 当前缺失，需新建 | **必须补，否则"权重"无从谈起** |

**总判断**：L2 自动/手动加因子 + L3 组合层 → **可行**，工程量中等（阶段一当天可用，全部完成 1~2 周）。L1 频繁扩特征 → 不建议，除非接受重训。

## 3. 第一个设计决断：决策树不做"预测器"

**不能用决策树做有监督预测**，理由是可算的：

- 候选因子总数 = 因子池 25 + 精英池 60，去重后约 **50~80 条**
- 每条样本的特征维度 **15~20 维**
- 样本/维度比 < 5:1，任何树模型都会把噪声背下来；交叉验证也无法挽救（样本本身有限）

**推荐定位：规则评分卡在前，浅树在后。**

1. 先用**显式规则**（硬门槛 + 分位打分）产出 `keep / watch / downweight / drop`
2. 再用**深度 ≤3 的 CART（带单调约束）**去拟合这套规则，作用是：
   - 把多维阈值压缩成可读的 if-else，便于审计与交接
   - 发现规则之间未预料到的交互（例如"高 IC 但高换手"这一支）
3. 树只做**分级**，不回归权重（树的输出是阶梯函数，直接当权重会导致权重跳变、换手爆炸）

若要真做有监督学习，唯一正确的样本构造是**面板样本**：`因子 × 评估窗口`，例如 50 因子 × 24 个月度窗口 = 1200 条，标签 = "下一窗口是否仍满足保留条件"。这要求先积累 3~6 个月台账（或回溯重放历史数据生成），属于阶段三。

## 4. 决策树输入特征（每条因子一个样本）

标注 `✔` = 现有代码可直接取，`＋` = 需新增计算。

| 组 | 特征 | 来源 |
|---|---|---|
| 收益 | 年化收益 `ann_ret`、累计收益、分年度收益 | ✔ `_multi_objective` |
| 风险 | Sortino、Calmar、最大回撤、收益波动 | ✔ `_sortino/_calmar` |
| 信号 | IC 均值、RankIC、ICIR、IC 的 t 值、方向稳定期占比 | ✔ `evaluator.score` |
| 衰减 | IC 半衰期、分层收益随持有期衰减 | ＋ |
| 稳健 | 4 折 WF 的 min/median/std、半程一致性、前后半段符号一致 | ✔ `_half_consistency_bonus` |
| 成本 | 换手率、成本压力测试后 Sortino、手续费占毛收益比 | ✔ `_cost_stress/_turnover_quality` |
| 暴露 | 仓位暴露度、Beta 中性度、多空对称性 | ✔ `_exposure_penalty/_beta_neutral_penalty/_symmetry_check` |
| 多样性 | 与保留集的最大相关、平均相关、消融边际贡献 | ✔ `evaluator.prune/ablate` |
| 生命周期 | 样本外/样本内比值、存续评估次数、最近 3 次综合分斜率 | ＋ |
| 元信息 | 公式长度、算子构成、类别（趋势/反转/量能…）、来源（自动/手动/外部库） | ✔ `vocab.py` |

**丢弃不用**：原始 token 序号、公式文本哈希（无泛化意义，会让树记住具体公式）。

## 5. 输出决策

四类离散标签 + 由标签映射权重，而不是树直接给权重：

| 标签 | 判定含义 | 权重动作 |
|---|---|---|
| `keep` | 达标且与现有池互补 | 维持/按评分卡给权 |
| `watch` | 边际达标，证据不足（样本少/IC 弱正） | 权重不变，缩短评估窗口，下次优先复评 |
| `downweight` | 未达标但未触发硬淘汰（相关性高、成本侵蚀、衰减中） | 权重 × 0.5，且设上限 |
| `drop` | 触发硬否决或连续 K 次未达标 | 权重归零，进入隔离期 |

输出结构（`decisions.json`）：

```json
{
  "generated_at": "2026-11-17T21:00:00+08:00",
  "window": {"start": "2025-01-01", "end": "2026-11-01"},
  "policy_version": "dt-v1",
  "items": [
    {"factor_id": "F0007", "label": "downweight", "weight": 0.08,
     "rule_hits": ["corr>0.85 with F0003", "cost_stress_sortino<0"],
     "score": 0.42, "quarantine_until": null}
  ]
}
```

## 6. 因子筛选与权重调整规则

### 6.1 第一层：硬否决（先于树，不进模型）

命中任一条即 `drop`，不参与后续打分：

1. 样本外年化 ≤ 0 **且** 样本外 Sortino ≤ 0
2. 成本压力测试后 Sortino < 0（成本敏感型因子死在实盘）
3. 有效交易样本 < 30 笔（统计不可判，直接排除而非保留）
4. 仓位暴露度 < 5%（信号几乎不出手，占位无意义）
5. 与保留集因子 `|corr| > 0.90` **且** 综合分低于对方（沿用 `evaluator.prune` 的保守双条件，避免误杀）

### 6.2 第二层：评分卡（0~1 连续分）

对通过否决的因子，各分项做**截面分位归一**后加权：

```
score = 0.30 * rank(ann_ret_oos)
      + 0.20 * rank(sortino_oos)
      + 0.15 * rank(ic_ir)
      + 0.15 * rank(wf_min)          # 最差那一折不塌，比均值重要
      + 0.10 * rank(cost_stress)
      + 0.10 * rank(1 - max_corr)    # 多样性溢价
```

### 6.3 第三层：分级映射

| 条件 | 标签 |
|---|---|
| `score ≥ P70` 且无否决 | `keep` |
| `P30 ≤ score < P70` | `watch` |
| `score < P30`，或 `max_corr > 0.85`，或 `ic_slope < 0` | `downweight` |
| 连续 3 次评估落入 `downweight` | `drop` |

### 6.4 权重公式与约束

```
raw_w  = score * (1 - max_corr)^1.5 * cost_discount
w_new  = clip(normalize(raw_w), 0.02, 0.30)
w_t    = 0.2 * w_new + 0.8 * w_{t-1}        # 平滑，抑制换手
```

硬约束：
- 单因子权重 ∈ [2%, 30%]（上限防集中，下限防占位）
- 权重集中度 HHI ≤ 0.25
- 每次调仓的组合换手上限 20%，超限则按比例压缩权重变动
- 被 `drop` 的因子进隔离期 60 个交易日，期间不得自动复活；仅允许手动恢复

## 7. 回测评估指标

| 层 | 指标 | 门槛/用途 |
|---|---|---|
| 单因子 | 样本外年化、Sortino、Calmar、MaxDD | 否决判据 |
| 单因子 | IC 均值、ICIR、t 值、方向稳定占比 | 信号质量 |
| 单因子 | 4 折 WF 的 min / std、半程一致性 | 稳健性（min 优先于均值） |
| 单因子 | 成本压力后 Sortino、换手率 | 可交易性 |
| 组合 | 组合年化、Sharpe、MaxDD、换手、Calmar | 组合验收 |
| 组合 | 因子边际贡献（逐一消融）、相关性矩阵、HHI | 归因与集中度 |
| 统计 | 尝试因子总数、参数组合数、BH-FDR / Deflated Sharpe | **多重检验校正，必做** |

**多重检验是硬要求**：这套流程每次都在几十个因子里挑，不校正就等于"测 100 个留 3 个"的过拟合机器。台账必须记 `n_tried`，每次决策报告要写校正前后的显著性。

## 8. 与现有流程的衔接（最关键的一条）

**决策树不能塞进训练循环。** 训练是秒级、决策是日级，节奏差 4 个数量级；把树放进 `for step in pbar` 里会导致每步重训、样本不足、抖动，并且污染 REINFORCE 的奖励信号。

正确形态是四段分离、异步回写：

```
① 挖掘（秒级）    train_file.py → 产出候选公式 → 写台账
② 评估（分钟~小时）批量回测 → 指标快照 → 追加到台账
③ 决策（日级）    决策树 → decisions.json
④ 组合（周级）    权重平滑 → 组合层 → 实盘信号
        ↑__________________ 淘汰结果回写 ① 的相关性惩罚基线
```

衔接要点：

1. **评估复用现有函数**：`evaluate_fold` 出 train/val 分，`evaluator.score_all/prune/ablate` 出信号质量与边际贡献，不要另写一套回测
2. **淘汰因子必须从 `factor_pool` 移除**：现在相关性惩罚拿全池当基线，若把已死因子留在池里，模型会被迫"绕开一个已经不该存在的东西"，扭曲搜索方向
3. **移除后需 `_invalidate_cache()` 并递增 `_fp_ver`**：相关性罚依赖池子，池子变了缓存必须失效（现有机制已支持）
4. **改池子后要做基准校准**：`RECALIBRATE_BEST_ON_RESUME` 已有逻辑，复用即可，否则 best_score 不可达、训练空转
5. **训练不中断**：台账与决策都是**旁路文件**，训练进程只读，不参与 checkpoint 写入，避免双写

## 10. 主要风险与注意事项

### R1（重大）当前回测的 purged gap 实际为 0，评估结论本身不可信

实测：`T=50000`、`n_folds=5` 时 `fold_size=10000`，`total_required = 50000 + 20×4 = 50080 > 50000`，触发 `engine.py:142` 的降级分支，`gap` 被压成 **0**。运行日志印证：`训练[0,10000) 间隔=0 验证[10000,20000)`。

后果：`target_ret[t] = log(open[t+2]/open[t+1])`，训练段最后 2 根 bar 的标签跨进了验证段——验证集并非严格样本外。**在这个基础上做淘汰决策，等于用有泄漏的分数决定因子生死。**

必须先在评估层修：`gap = max(WF_GAP, horizon)`，且数据长度不足时应缩折数而不是把 gap 归零。`IF_RISK`：若不做，所有下游结论降级为"待验证"。

### R2（重大）小样本 + 多重检验 → 淘汰规则自身过拟合

50~80 个样本上做多维筛选，天然会挑到噪声。缓解：规则先行、树深 ≤3、单调约束、淘汰需连续 3 次、记录 `n_tried` 并做 BH-FDR 校正。

### R3（较大）权重跳变吃掉全部超额

因子评分每周都在变，若权重直接跟随评分，组合换手会从 20%/月涨到 200%/月。缓解：`W_SMOOTH=0.2`、单次换手上限、权重上下限。

### R4（较大）淘汰不可逆 → 因子枯竭

`MAX_RESTARTS` 与隔离期都会减少候选。若淘汰过严，池子会空。缓解：隔离期 + 复活机制（连续 3 次 `keep` 自动恢复），且 `drop` 只在"硬否决"时不可逆。

### R5（较大）L1 特征变更会废掉全部 checkpoint

`VOCAB_VERSION` 是 token 名 SHA256，新增一个特征就会改变词表 → 旧 checkpoint 的 token 索引全部错位。若因子库要扩特征，必须接受从头训练，且不能与正在跑的训练并行。

### R6（一般）单品种 N=1，截面类特征失效

`_normalize_output` 在 `N>1` 时走截面标准化，单品种走时序标准化。组合层引入多因子后 `N` 会变大，**必须显式传 `cross_section` 开关**，不能靠 `N` 的数值判断，否则因子语义被静默改写。

### R7（一般）未来函数与数据可得时点

外部因子库（尤其基本面类）存在"财报可得时点"问题，必须按公告日而非报告期对齐；`evaluator._align_causal` 已处理 target 端，但因子端需调用方保证。

### R8（提示）决策树可解释 ≠ 正确

树学到的是"这批因子在历史窗口上的规律"，不是因果。报告里要写清窗口、样本量、校正结果，避免把 `feature_importance` 当结论。

## 11. 实施顺序

| 阶段 | 内容 | 产出 | 依赖 |
|---|---|---|---|
| **0（半天）** | 修 `WF_GAP` 降级问题 + 台账骨架 | 可信的评估基线 | 无 |

阶段一的规则评分卡**不需要任何机器学习**，当天就能给出"哪些因子该弱化"，是最小可用版本。

## 12. 待确认

1. "新因子"指 L2（新公式，零成本）还是 L1（新特征，需重训）？还是外部因子库的预计算序列（需走 `[N,T]` 旁路）？
2. 组合层的目标是"多因子加权持仓"还是"多策略并行分账户"？前者是向量加权，后者是资金分配，实现完全不同。
3. 因子评估频率：每日收盘一次，还是每 N 个训练步一次？前者贴近实盘，后者贴近挖掘节奏。
