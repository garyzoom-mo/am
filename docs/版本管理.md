# 版本管理

AlphaMaster 从 2026-11-22 起纳入 git 管理。本文说明**什么进了仓库、什么没进、模型版本怎么追溯**。

仓库位置：`E:\工作\AlphaMaster`，分支 `main`。

---

## 一、三类东西，三种管法

训练项目的特点是「代码小、产物大」。把所有东西塞进 git 会让仓库涨到 13GB 且无法 clone，
所以分三层管：

| 层次 | 内容 | 载体 | 能否回滚 |
|---|---|---|---|
| **代码层** | 训练引擎、评分公式、回测、数据管道、web/paper | git（235 个文件，约 19MB） | 能，`git checkout <commit>` |
| **公式层** | `strategies/best_<SYM>.json`（每次训练的最优公式 + 分数） | git（每个不到 200 字节） | 能，`git log -p` 看每次训练改了什么 |
| **权重层** | `checkpoints/ckpt_<SYM>_step_<N>.pt`（20MB/个） | 本地文件 + `CKPT_INDEX.tsv` 记录 | 能定位、能验完整性，但不进 git |

权重层不进 git 的原因很直接：167 个检查点 5.39GB，git 存二进制会全量复制，
commit 一次涨 5GB 且永远删不掉。

## 二、模型版本怎么追溯

一个模型版本 = **代码 commit + 公式文件 + 检查点哈希**，三者能对上就完整可复现。

### 查某个检查点是什么时候、哪次训练产生的

```bash
# 清单里按品种和步数查，带 sha256 和生成时间
grep "BTCUSDT.*step_2000" CKPT_INDEX.tsv

# 输出示例
# BTCUSDT  2000  23.3  2026-11-20 22:42  a1b2c3...  ckpt_BTCUSDT_step_2000.pt
```

### 查某次训练用的什么代码

```bash
# 训练产出的公式文件会跟着提交，看它的历史就知道每次训练的差异
git log --oneline -- strategies/best_BTCUSDT.json
git show <commit>:strategies/best_BTCUSDT.json
```

### 验证检查点有没有被改动或损坏

```bash
python tools/ckpt_index.py --check
```

逐个重算 sha256 与清单比对，报出 `[变更]` / `[缺失]`。7.5GB 大约一两分钟。

### 清单怎么更新

```bash
python tools/ckpt_index.py          # 增量：大小和修改时间没变就复用旧哈希
git add CKPT_INDEX.tsv && git commit -m "chore: 更新检查点清单"
```

训练中新产生几个检查点时只有新增的会被哈希，秒级完成。`--full` 强制全量重算。

## 三、没进仓库的东西

| 路径 | 体积 | 原因 |
|---|---|---|
| `checkpoints*/` | 7.5GB + 3.2GB | 检查点与历史备份，二进制且可再生产 |
| `_backup_ckpt_*/` `_install_temp_backup_*/` | 107MB | 一次性备份 |
| `.venv/` | — | 虚拟环境，`pip install -r` 可重建 |
| `data/` `*.parquet` | — | 行情缓存，机器相关且体积大 |
| `logs/` `backtest_output/` | — | 运行产物 |
| `.env` | 257B | **交易所密钥，绝不入库** |
| `training_history*.json` | — | 每步都写，高频变动 |

`checkpoints_bak_20261120_1608_before9y/`（3.2GB）是 9 年重训前的人工备份，
确认新版本稳定后可以删掉，删之前先跑一次 `--check` 确认在册检查点都在。

## 四、日常怎么用

### 改评分公式 / 训练参数前

先提交，让「改之前」有个干净的落点：

```bash
git add -A && git commit -m "chore: 改动前的基线"
```

改完训练出结果，再提交一次。两次 commit 的 diff 就是这次实验的全部变量，
以后看到某个模型表现异常，`git log` 能直接定位当时改了什么。

### 一次训练实验的标准流程

```bash
# 1. 记录起点
git commit -am "exp: 9年全量 + 熵上限2.0 的基线"

# 2. 训练（产物写入 checkpoints/ 与 strategies/best_<SYM>.json）

# 3. 更新清单并提交结果
python tools/ckpt_index.py
git add CKPT_INDEX.tsv strategies/ 
git commit -m "exp: 9年全量重训，最优 1.0445，治理层全盘否决"
```

commit message 里写清**结论**（不只是「训练完成」），三个月后回看才知道该不该复用这一版。

### 回滚

```bash
git log --oneline                    # 找到目标 commit
git checkout <commit> -- model_core/backtest.py   # 只回滚单个文件
git revert <commit>                  # 整体回滚（保留历史）
```

### 打标记

重要版本打 tag，比翻 commit hash 快：

```bash
git tag -a v2026.11-9y -m "9年全量训练版本，治理层否决"
git tag                              # 列出所有版本
```

## 五、提交规范

沿用 `缠论助手/factor-governor` 的格式：

```
<type>(<scope>): <一句话说明>

<为什么改，不写「修改了什么」——diff 已经写了>
```

type：`feat` 新增能力 / `fix` 修 bug / `perf` 性能 / `exp` 训练实验 / `chore` 杂项 / `docs` 文档。

重点在正文说明**动机和结论**。例如：

- ✅ `fix(backtest): evaluate_fold 在全长上算仓位后切片，4 折浪费 85%`
- ❌ `修改 backtest.py`

- `.git-rewrite/` 是之前某次 `filter-branch` 被中断的残留，没有 `.git` 时无意义，
  已加入忽略规则，可以随时删除。
- 仓库目前**没有远程**。要备份到 GitHub 需先建空仓库再 `git remote add origin`，
  注意首次 push 前确认 `git status` 里没有 `.env`。
